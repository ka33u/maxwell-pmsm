## Tool routing

- The local 2023 R2 executable is `E:\AnsysEM\v232\Win64\ansysedt.exe`. The earlier 2021 R1 run used `D:\Program Files\AnsysEM\AnsysEM21.1\Win64\ansysedt.exe`. Check the executable and reported release before launching. A stale `ANSYSEM_ROOT211` can survive an upgrade. For the native runner use `& '<actual ansysedt.exe>' -RunScriptAndExit '<absolute case runner.py>'`; this executes inside AEDT. For the external CPython/gRPC path see [MCP](mcp-2023r2.md).
- Run offline audits with a working CPython, e.g. `& '<python.exe>' '<skill>\scripts\audit_case.py' --case '<case-dir>' --kind load --out '<new-output.json>'`. The WindowsApps alias may exist even when it cannot run Python. The 2023 R2 no-load case passed the same case-layout audit as its 2021 R1 baseline. See `upgrade_validation_2023R2_20261121/75kW_Maxwell版本升级复算.md` in the workspace for raw evidence, short-path retry conditions and the material warning.
- Generic workflow: `preflight_new_motor.py` checks supplied input structure, not actual model geometry; `generate_full_noload_case.py` starts from a previously checked **full** 2D Transient geometry; then `generate_full_loaded_case.py` starts from the successfully completed no-load case. `summarize_full_loaded_case.py` summarizes the load. The tool package README documents arguments and object names. These tools do not read arbitrary EXB/DWG into validated geometry.
- Each script's output destination must not already exist. For full models the geometry convention is `Stator`, `Rotor`, `Band`, rectangular `Region`, `PM_*`, and `Coil_XX_Upper/Lower`. Review object count, closed areas, actual units, overlap, shaft, motion band, PM material and local axes. A successful `ValidateDesign` is not physical validation.
- Generic winding import is for uniform turns; it cannot represent mixed turns. If the exact use case is 72 slots, 12 poles, pitch 5 and **12 branches per phase, two coils per branch**, `mixed_turns_72s12p/prepare_mixed_turns_noload.py` accepts per-coil turns. Its candidate CSVs are illustrative only and cannot certify actual wiring. For other mixed-turn or branch topologies, adapt and test rather than forcing the 72-slot adapter. `mixed_turns_72s12p/README.md` documents inputs and commands.
- For candidate tables in the documented complete two-layer format, [ideal winding phasors](winding-check.md) can screen per-branch polarity and ideal fundamental imbalance with explicit slot/pole/pitch/branch parameters; it is not a measured branch EMF or proof of actual wiring or circulating currents.
- `mixed_turns_72s12p/calibrate_noload_emf.py --csv <noload_EMF.csv> --frequency-hz <f> --out <new.json>` fits phase and produces trial angles. `prepare_load_sequence.py` makes a single load case and explicitly accepts `--phase-sequence ABC|ACB`; compare actual EMF and current waveforms. Generic `prepare_full_load_sweep.py --source-case <completed-noload> --spec <cases.json> --out <new-dir>` prepares, but does not solve, up to 64 cases; its generator assumes ABC. `inspect_full_load_sweep.py` checks progress. Do not use it unchanged for ACB.
- `generate_full_coreloss_case.py` adds a fit from `fit_steel_coreloss_csv.py` / `cross_validate_steel_coreloss_csv.py`; fitting needs a Python with NumPy. It uses the ABC load generator, disables steel solid eddy, sets empirical core loss without field feedback and does not explicitly set Kdc. For ACB, adapt and verify before use. `--magnet-eddy` enables each PM's 2D solid eddy current with individual zero-net-current condition; verify saved settings and outputs. A Band edge constraint is not a PM interior mesh constraint.
- For the local generated load-case layout, prefer `scripts/audited_compare_loaded.py --comparator '<workspace>\compare_loaded_timestep.py' --coarse <case> --fine <case> --vary timestep|band --out <new.json>`; it first audits both cases, verifies a common accessible source, and rejects runner differences except their own checked configuration digest. It retains warnings and fingerprints the explicitly selected comparator and dependencies. It is deliberately strict and may reject differently generated but equivalent runners; neither it nor the original `compare_loaded_timestep.py` establishes solver provenance or comprehensive mesh convergence. See [verification](verification.md). `compare_adjacent_mechanical_turns.py` is restricted to its 8-pole example and cannot certify the 12-pole machines. The mixed-turn two-cycle load and loss audit scripts are similarly case-limited. Adapt and test a new comparison for other cycle counts or models.

## Explicit local evidence

The 30 kW example's quick half model is not a general half-model template. The 110/75 kW studies in `two_motor_simulation_20261119/两规格_仿真对比.md` used dedicated geometry reconstructed from marked dimensions after the user confirmed the stator drawings were not to scale. They used 12-pole/72-slot mixed-turn candidate windings, reference steel, straight slots and a single load angle. Iron loss increased about 21% between the first and second electric cycles; it was not stable. Do not reuse those motor dimensions, electrical settings or assumptions as defaults for another model.

For other environments, choose a compatible documented backend and verify a small isolated example; do not change installed versions or existing projects merely to use this skill. The official PyAEDT example is useful as a reference for sector models, dq reports and loss setup: https://github.com/ansys/pyaedt-examples/blob/main/examples/low_frequency/motor/aedt_motor/pm_synchronous.py . It is a specific 48-slot/8-pole model and is not evidence that a new motor or version is validated.
